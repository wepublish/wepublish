---
title: Print issues: print lists, deliveries and supplements
lead: Under «Print issues» you create each printed issue, compute who receives a copy as of its ship day, export the print list, download its CSV and mark it as delivered to the printshop. Delivered print lists count toward the issues each reader paid for.
actionRequired: false
---

Available for media with the print export switched on.

- **Each issue is a record**: number, ship day, a note and an image (e.g. the cover), in a form next to the issue list. The list shows the status (Open, Exported, Closed, Historic), the print lists, the copies and who closed the issue; «Duplicate» creates the next number with the same options, and a new issue is prefilled the same way. Who receives a copy is decided **as of the ship day**, not the day you export – an issue shipped in January lists the January subscribers.
- **Double issues and topic**: an issue can cover two numbers («to number», e.g. 3/4.26). It then counts as two of the issues a period paid for; per issue you can let it count as one. Readers owed only one more copy still receive the double issue. Single-copy orders in bexio naming «3/4.26», «3.26» or «4.26» all count for this issue. Each issue can also have a topic; show the «Topic» column in the issue list through the column picker.
- **Print lists first**: an issue's view starts with its print lists – the print list and its supplements, each with its own options, totals and CSV file. One button below the table offers the next step: «Create print list», «Edit print list» while it is a draft, or «Create supplement» once the last one is delivered.
- **Options → check → export**: pick the plans, whether bexio is read (institutions, gifts, bookshops, single issues – through the bexio payment provider's key under Integrations), whether «open» readers with an unpaid renewal receive a copy and whether subscriptions starting after the ship day get a gift copy; the defaults live under Settings → Plans. «Compute» stores the options on the issue and computes the list; you check its totals and every address; «Export print list» writes exactly that list. Editing a draft runs the same steps and updates it in place; a list older than 24 hours must be computed again.
- **bexio delivery types**: under Settings › Print issues you define how the print list recognises orders in bexio – per delivery type a label, a keyword and whether a period or an issue follows. Broker and gift subscriptions: the keyword starts the description of the contact link (e.g. «NW Geschenkabo»), the period is in the invoice title (year «2027» or «15.03.2026–14.03.2027»); every linked person receives a copy while the ship day lies in the period, afterwards copies still owed up to its share of «Issues per year». Single issues: invoice position «Einzelheft 6.26», the quantity counts. Only complete entries select; anything else counts as «without a valid period or issue». Each print list chooses the delivery types it reads; without one nothing is listed from bexio.
- **Mark as delivered**: once the file is at the printshop, mark the print list as delivered. It is frozen from then on and its copies count toward the paid issues – drafts do not count yet. «Take back the delivery» makes the newest print list of the newest issue with print lists a draft again – to correct it, deliver it anew or delete it; its copies do not count meanwhile, and the issue can then be deleted too. The issue list marks issues with a draft, and checking a list warns when an issue shipped earlier still has one. Corrections become a **supplement** from there: the same steps, only with the addresses in no earlier print list of the issue – as its own list with its own file. The complete list of all print lists is available at any time.
- **Close**: once every print list is delivered, close the issue; «Unlock» undoes that at any time should a supplement still be needed. Historic issues from the import are closed for good. An issue can be deleted only while none of its print lists is delivered. In the issue list, the tooltips of the lock and the bin explain why each action is or is not available.
- **Copies owed**: the setting «Issues per year (print)» and, on a plan per payment periodicity, «Printed issues per period» (e.g. 3 for a trial, or 1 monthly and 6 yearly in the same plan; 0 means no printed issues) say how many printed issues a paid period is worth. A reader whose paid period ended still receives copies until that number is reached – for the time of two issues after the period ends (four months at 6 issues per year), then the subscription is simply over. The issues shipped before the feature existed come in through the import as historic issues, so the current year counts. The bexio overview now also shows how many invoices the payment provider created itself and how many are imported legacy invoices.
